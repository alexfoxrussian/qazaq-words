# Архитектура MVP

## Стек и ответственность
React + TypeScript отвечает за UI, Vite — за разработку и сборку, React Router — за шесть маршрутов, Zustand — за оперативное состояние, Dexie/IndexedDB — за долговременные данные. Рабочий выбор оформления: CSS Modules и общие CSS variables; Lucide React для иконок, SVG и доступная таблица для графика активности. Для PWA использовать интеграцию service worker с Vite; версии зависимостей подобрать и зафиксировать при реализации.

Backend отсутствует. Приложение публикуется как статические файлы по HTTPS; localhost подходит для разработки. У хостинга должен быть SPA fallback. Данные принадлежат origin, смена домена требует переноса JSON backup.

## Структура
```text
src/
  app/                 # запуск, router, providers, shell, service worker
  pages/               # dashboard, training, dictionary, statistics, profile, settings
  features/            # training, word-management, profiles, import-export, appearance
  entities/            # word, topic, profile, progress, training-session, answer
  shared/
    db/                # Dexie, миграции, репозитории
    ui/                # Button, BentoCard, Modal, EmptyState, FormField
    utils/             # нормализация, даты, идентификаторы
  styles/              # токены, базовые стили, варианты оформления
```
Зависимости направлены от app/pages к features/entities/shared. Доменные функции не зависят от UI. Сущности WordSet нет.

## Маршруты
`/` — Главная; `/training` — Тренировка; `/dictionary` — Словарь; `/statistics` — Статистика; `/profile` — Профиль; `/settings` — Настройки. На неизвестном адресе показать состояние ошибки внутри shell с возвратом на главную. При отсутствии активного профиля перенаправлять на `/profile`; восстановление backup доступно из состояния первого запуска.

## Модель данных
Идентификаторы — UUID, даты — epoch milliseconds UTC. Версия Dexie и версия формата backup независимы.

| Таблица | Поля и ключи |
| --- | --- |
| profiles | id, name, createdAt, updatedAt |
| words | id, kazakh, russian, topicIds[], createdAt, updatedAt |
| topics | id, name, createdAt, updatedAt |
| progress | составной PK [profileId+wordId], stage (0–5), dueAt, lastAnsweredAt, correctCount, incorrectCount |
| sessions | id, profileId, status (active/completed/interrupted), startedAt, endedAt?, targetCount, answeredCount, correctCount, queueSnapshots[], cursor |
| answers | id, sessionId, profileId, wordId, questionIndex, kazakhSnapshot, russianSnapshot, optionsSnapshot[], selectedIndex, correctIndex, isCorrect, answeredAt |
| settings | PK profileId, colorMode, palette, visualStyle, sessionLength |
| appMeta | key, value; activeProfileId и признак инициализации |

Индексы: progress `[profileId+dueAt]`; sessions `[profileId+startedAt]`; answers `[profileId+answeredAt]`, sessionId и уникальный `[sessionId+questionIndex]`; words multiEntry `topicIds`; остальные — по потребностям запросов. Ссылочную целостность обеспечивает слой репозиториев и валидатор backup, а не сама IndexedDB.

`queueSnapshots` содержит wordId, текст вопроса, четыре перевода и правильный индекс. Снимки стабилизируют сеанс после перезагрузки. Продолжение активно только для его владельца. Смена профиля или изменение словаря во время сеанса сначала завершает его как interrupted; предыдущие ответы сохраняются.

## Состояние и доступ к данным
Zustand хранит загрузку, активный профиль, фильтры, оформление и текущее представление сеанса. Репозитории профилей, словаря, тренировки и backup выполняют чтения/записи Dexie. UI получает реактивные выборки, например через Dexie live queries. При загрузке приложения настройки и активный сеанс восстанавливаются из базы. UI не должен показывать успешный ответ до подтверждённой записи; при ошибке записи предлагается повторить операцию без двойного учёта.

## Домен тренировки
1. Получить слова выбранных тем и прогресс профиля.
2. Отсортировать просроченные по dueAt; затем добавить новые в стабильном порядке создания. Отсутствие progress означает новое слово. Затем добавить слова с будущим dueAt по ближайшему сроку и стабильному порядку создания. Следующий сеанс доступен сразу.
3. Отсеять вопросы без трёх уникальных неверных переводов. Для отвлекающих ответов использовать весь словарь, исключая все переводы того же нормализованного казахского слова.
4. Ограничить очередь sessionLength; перемешать варианты каждой карточки и сохранить снимки сеанса.
5. На ответ вызвать чистую функцию `evaluateAnswer` и `scheduleNextReview`, затем транзакцию answers + progress + sessions.
6. Уникальный ключ ответа и проверка cursor обеспечивают идемпотентность. Счётчики меняются только при создании нового ответа.

Алгоритм из PRD: при correct `stage = min(previousStage + 1, 5)`, интервал берётся из `[1, 3, 7, 14, 30]` для ступени 1–5; при incorrect stage=0, dueAt=now+10 минут. Для нового слова previousStage=0. Одни сутки интервала — 24 часа, а не смена календарного дня. Часы устройства — источник времени MVP.

После ответа cursor указывает следующий вопрос, а UI может продолжать показывать результат предыдущего. При восстановлении использовать последний answer, чтобы показать результат до явного перехода. Последний ответ завершает сеанс атомарно; итог доступен после перезагрузки. Закрытие вкладки не помечает сеанс interrupted: следующий запуск предлагает продолжить или завершить его.

## Статистика и изменения словаря
Графики и точность вычисляются по answers активного профиля; даты группируются в текущей локальной зоне. Агрегаты не являются отдельным источником истины. Удаление слова атомарно удаляет progress по wordId, но сохраняет ответы со снимками. Изменение текста атомарно сбрасывает progress слова у всех профилей. Удаление темы убирает её id из words; слова остаются. Удаление профиля каскадно удаляет его settings, progress, sessions и answers и корректирует activeProfileId.

Репозиторий словаря проверяет нормализованные дубли внутри той же транзакции, что выполняет запись, чтобы параллельные вкладки не создавали дубли. Нормализованные названия тем уникальны (рабочее решение). Устаревшие формы редактирования отклоняются, если исходная запись изменилась. Подтверждение сброса прогресса, удаления или прерывания активного сеанса запрашивается до записи; отмена не меняет базу.

## Backup
```json
{
  "format": "qazaq-words-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-10-09T12:00:00.000Z",
  "data": {
    "profiles": [], "words": [], "topics": [], "progress": [],
    "sessions": [], "answers": [], "settings": [], "appMeta": []
  }
}
```
Экспорт читает согласованный снимок всех таблиц одной readonly-транзакцией. Импорт сначала проверяет format, поддерживаемую версию, типы, диапазоны, уникальность ключей, ссылки, индексы вариантов, правильность ответов и согласованность сеансов. Исторический answer.wordId может ссылаться на удалённое слово; остальные живые ссылки обязаны существовать. Неподдерживаемую будущую версию отклонять. Более старые поддерживаемые версии преобразовывать до записи.

Рабочие ограничения: файл до 25 MiB, непустые строки слова/перевода до 200 символов, имена профилей/тем до 80. Показывать предварительное количество сущностей и предупреждение о полной замене; предложить экспорт текущих данных. Замена всех таблиц — одна readwrite-транзакция с rollback при любой ошибке. На время восстановления блокировать записи интерфейса. Backup содержит пользовательские данные; загрузка и чтение выполняются локально.

## PWA и сбои
Manifest: имя, иконки, standalone, start_url. Service worker кеширует shell, JS/CSS, локальные шрифты и иконки. IndexedDB хранит содержимое и не подменяется кешем. Нет обязательных CDN, внешних шрифтов или сетевых запросов. Первый запуск требует загрузки ресурсов; готовность offline показывать после установки кеша. Обновление service worker применять по предложению пользователя после сохранения текущего ответа. Новая сборка должна уметь мигрировать прежнюю базу.

При недоступной IndexedDB или исчерпанной квоте не переходить молча на временное хранение: показать ошибку и варианты повторной попытки/экспорта, если чтение ещё доступно. Не обещать защиту локальных профилей паролем; профили служат разделению прогресса на одном устройстве.


## Уточнения интерфейса и переноса — 2026-10-10

Перенос словаря: format=qazaq-words-dictionary, version=1, topics — массив названий, words — массив {kazakh, russian, topics: string[]}. Лимит 25 MiB. Валидатор проверяет типы, длины, нормализованные дубли и ссылки на темы до записи. Репозиторий экспортирует согласованный снимок. Импорт в одной транзакции объединяет темы по названию и слова по паре нормализованных текстов, объединяет topicIds без изменения текста и прогресса, прерывает активные сеансы после подтверждения. UUID и даты назначаются локально. Настройка длины сеанса записывается через репозиторий с проверкой активного владельца.


Уточнение длины сеанса (2026-10-10): варианты 10, 20, 30, «Свой вариант» (целое положительное число с явным сохранением) и «Весь словарь» (все пригодные слова выбранной темы). Настройка сохраняется для профиля; sessionLength=0 означает отсутствие лимита, прежние числовые настройки сохраняются. Кнопка «Обновить очередь» удалена: очередь обновляется автоматически. Это заменяет прежнее ограничение 5–30.

Представление итога завершённого сеанса сбрасывается в prepare при изменении ключа навигации React Router, включая повторный переход на /training. Сброс касается только UI; IndexedDB и активные сеансы сохраняются.

Статистика читается согласованной readonly-транзакцией, только для выбранного profileId. Периоды 7/30 включают сегодня и предыдущие 6/29 локальных календарных дней. Будущие ответы не учитываются. Серия — общая текущая, заканчивается сегодня или вчера. «Всё время» показывает только дни с ответами; периоды 7/30 включают нулевые дни. Завершённые сеансы фильтруются по endedAt. Распределение ступеней и счётчики новых/изучаемых слов относятся к текущему словарю независимо от периода.

Этап 6: AppearanceProvider применяет colorMode/palette/visualStyle через data-атрибуты корня и CSS-токены, системная тема отслеживается через matchMedia. SettingsRepository проверяет активного владельца и сохраняет оформление без изменения длины сеанса. Полный backup v1 проверяет все таблицы, уникальность ключей, владельцев, нормализованные дубли, живые ссылки, варианты/ответы, счётчики и порядок сеанса. Снимки неактивных сеансов могут ссылаться на удалённые слова. Более ранних поддерживаемых версий пока нет. Замена всех таблиц выполняется одной транзакцией; текущие сеансы заменяются состоянием из копии после явного подтверждения. При восстановлении UI перечитывает профиль и тренировку. Экспорт и импорт до 25 MiB; формат переноса словаря остаётся отдельным.


## Правки интерфейса — 2026-10-10

Размер шрифта сохраняется для профиля: standard (исходный), large (+2 px), maximum (+4 px), выбирается в Настройках. Все текстовые CSS-токены учитывают прибавку, включая навигацию и формы. Длина сеанса выбирается только перед тренировкой; отдельная карточка в Настройках удалена.

Общий контент выровнен сверху, шапка закрепляется при прокрутке. Слова и переводы расположены в строке с кнопками-иконками карандаша и корзины; темы используют те же доступные кнопки с подписями и областью 44×44 px. На узких экранах перевод переносится под слово, действия остаются справа.

Активность — календарь квадратов: понедельник сверху, недели по колонкам, пустые дни сохранены; насыщенность показывает число ответов. Периоды 7/30 дней соответствуют выбранному диапазону. При выборе всего времени календарь показывает последние 365 дней, а показатели и доступная таблица сохраняют всю историю. Значения дня доступны через фокус, подпись и подсказку.

Dexie v2 добавляет fontSize=standard существующим настройкам без удаления данных. JSON backup остаётся версии 1: fontSize экспортируется и проверяется, старые файлы без поля получают standard, входной объект не изменяется.


## Фото профиля и favicon — 2026-10-10

В шапке имя активного профиля увеличено до 18 px (плюс настройка размера), рядом круглая фотография 44 px. На странице профилей можно загрузить/заменить/убрать фото любого локального профиля. Принимаются JPG, PNG, WebP до 5 МБ и 25 миллионов пикселей, изображение автоматически обрезается по центру и сохраняется как JPEG 256×256. Обработка происходит в браузере без загрузки на сервер.

Профиль содержит необязательное avatarDataUrl, запись выполняется через репозиторий транзакционно. Dexie v3 сохраняет существующие профили без очистки, их фото первоначально отсутствует. Backup версии 1 включает фото; старые файлы без поля принимаются. Валидатор разрешает только ограниченный по размеру JPEG data URL; внешние адреса и SVG отклоняются до записи. Favicon — локальный SVG с буквой Q в синем квадрате.

shadcn/ui рассмотрен; в текущей правке не подключается. Проект сохраняет CSS Modules и общие токены оформления. Возможный постепенный переход требует отдельной настройки Tailwind и адаптации компонентов к палитрам, стилям и размеру текста.


## Стиль Modern New — 2026-10-10

Добавлен отдельный visualStyle=modern-new с названием Modern New в Настройках. Прежний modern остаётся доступным и значением по умолчанию; существующие настройки не заменяются. Выбор сохраняется для профиля и включается в backup версии 1. Структура базы не меняется; новая миграция Dexie не требуется.

Modern New использует общие страницы и компоненты, отдельные CSS-правила ограничены data-style=modern-new. Композиция главной: компактная карточка запуска с типографической иллюстрацией и карточка реального прогресса общего словаря, затем показатели профиля. Подготовка тренировки имеет два столбца на широком экране; вопрос выделен мягким фоном, номера ответов — отдельными маркерами, правильный/неправильный ответ — цветом и текстом. Словарь использует более плотные строки и компактные темы. Навигация, кнопки, поля и карточки получают общую геометрию, спокойные тени и небольшие переходы. Для reduced-motion анимация и переходы отключены.

Стиль поддерживает прежние палитры, светлую/тёмную/системную тему, размеры шрифта и мобильную навигацию. Дополнительные элементы композиции скрыты в старых стилях; функциональность тренировки, словаря и статистики единая. shadcn/ui не подключается.


## Словарь: сортировка и страницы — 2026-10-10

В блоке «Слова» доступны сортировка по казахскому слову (алфавит kk), русскому переводу (ru) и дате добавления, в обоих направлениях; исходный порядок — казахский алфавит. Сначала применяются поиск и фильтр темы, затем сортировка и пагинация. Размер страницы: 10/20/50, по умолчанию 20. При смене фильтра, сортировки или размера открывается первая страница; после удаления последней записи страницы номер ограничивается существующими страницами. Нижняя панель показывает диапазон, количество найденных слов, номер страницы и кнопки «Назад»/«Далее»; прежняя строка «Показано слов» удалена. Состояние списка хранится только в Zustand.

Импорт/экспорт перенесены в блок «Слова», отдельный блок переноса удалён во всех стилях. Экспорт включает весь словарь и темы независимо от фильтров и страницы; проверка JSON, подтверждение и атомарность импорта сохранены.


## Гость и локальный вход — 2026-10-10

Вход означает выбор локального профиля без пароля; регистрация — создание профиля с именем, фото можно загрузить в Профиле. Последний выбранный профиль восстанавливается при запуске. Отсутствие activeProfileId означает гостевой режим; первый запуск открывает главную. «Выйти» в Профиле транзакционно сбрасывает activeProfileId; активный сохранённый сеанс требует прежнего подтверждения прерывания. Профили, прогресс и история не удаляются.

Гость может просматривать общий словарь с поиском, сортировкой и пагинацией, но не изменять, импортировать или экспортировать его. Тренировка доступна гостю на общей базе слов и с прежним единственным режимом. Вопросы, ответы, длина, счётчики и итог гостя существуют только в памяти, без гостевого профиля или записей в IndexedDB/localStorage. Перезагрузка сбрасывает гостевой сеанс; вход в профиль также очищает его. Проверка ответа и построение очереди используют общую доменную логику; интервальный прогресс гостя не записывается. Статистика и Настройки без профиля показывают приглашение войти.

Шапка с профилем удалена на всех экранах. Главная гостя содержит «Новые слова. Знакомый язык», «Войти» и «Начать тренировку». После входа вместо этого заголовка показаны «Сәлем, {имя}», фото и прогресс-бар доли слов на ступени 5 во всём общем словаре, без видимых чисел. Смена профиля и выход доступны в пункте навигации «Профиль». Гость использует системную цветовую тему и Modern New, его настройки не сохраняются. Новая схема базы и миграция не требуются; словарь не заполняется автоматически.


Уточнение прогресс-бара главной (2026-10-10): вместо доли слов на ступени 5 используется сумма текущих ступеней слов / (количество слов × 5). Новые слова и ступень 0 дают нулевой вклад, удалённые слова исключены. Пустой словарь — 0. Видимые числа не добавляются; доступное название — «Средний прогресс изучения слов словаря». Показатель рассчитывается в доменной статистике, интервалы и критерий полностью изученного слова не меняются.


## Четыре обновлённых стиля — 2026-10-10

Старый вариант Modern удалён; Modern New переименован в Modern с canonical visualStyle=modern. В Настройках ровно четыре стиля: Modern, Retro, Pixel, Orient. Существующий modern теперь использует обновлённое оформление; Dexie v4 переименовывает modern-new в modern без удаления пользовательских данных. Backup версии 1 принимает старый modern-new и нормализует его в modern на копии объекта; экспорт использует canonical значение.

Все четыре стиля используют общую обновлённую композицию шести экранов, включая предпросмотр, таблицу слов, карточки профилей, календарь и тренировку. Retro — бумажный фон, печатная типографика, двойные/пунктирные линии и смещённые тени. Pixel — клетчатый фон, моноширинные заголовки, прямые углы, квадратные маркеры и ступенчатые тени. Orient — геометрический фон, арочная иллюстрация, двойные рамки, ромбовые маркеры и асимметричные скругления. Палитра акцента остаётся отдельной настройкой; светлая/тёмная/системная тема, размеры шрифта, клавиатура и reduced-motion поддерживаются. Страницы не копируются, оформление задаётся общими токенами и CSS Modules. Гость использует обновлённый Modern.


## Реализация PWA — 2026-10-12

Используются vite-plugin-pwa 2.0.0 и workbox-window 7.4.1. GenerateSW создаёт precache shell, HTML, JS/CSS, локальных woff/woff2 и PNG/SVG. Runtime caching внешних запросов отсутствует; IndexedDB остаётся единственным долговременным хранилищем данных. navigateFallback отдаёт index.html для офлайн-маршрутов. Manifest и роутер учитывают Vite base, иконки включают maskable и apple-touch-icon.

Регистрация выполняется один раз вне React в features/pwa/runtime.ts и только для production. Общий PwaControls показывает готовность кэша, установку, проверку и предложение обновления. Используется prompt-стратегия: SKIP_WAITING отправляется после подтверждения; перезагрузка допускается только после одобрения этой вкладки и при отсутствии активной тренировки, включая гостевую. Активация из другой вкладки не перезагружает текущую. Проверка версии выполняется при восстановлении сети, возвращении в окно не чаще часа и вручную. Схема Dexie v4 не меняется.


### HTTP на телефоне — 2026-10-13

При запуске PWA проверяются isSecureContext и наличие navigator.serviceWorker до регистрации. На HTTP в локальной сети или в неподдерживаемом браузере отображается причина недоступности офлайн-режима, регистрация и проверка обновлений не запускаются. Ошибка регистрации также заменяет статус подготовки на недоступность.

Идентификаторы создаются через общий createId: native randomUUID при наличии либо UUID v4 на getRandomValues для HTTP в локальной сети. Формат ключей сохраняется, миграция базы не требуется. Репозитории профилей, словаря, тренировок и гостевые сеансы используют этот helper. Источник: https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues.
