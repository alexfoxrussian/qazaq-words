# Qazaq Words — инструкции для Codex

## Назначение

Создать локальный тренажёр казахских слов для русскоязычного пользователя. Требования: [PRD](docs/PRD.md), [архитектура](docs/ARCHITECTURE.md), [план](docs/IMPLEMENTATION_PLAN.md), [дизайн](docs/DESIGN_SYSTEM.md), [сценарии](docs/USER_FLOWS.md).

Этот комплект предназначен для корня отдельного рабочего репозитория. Если он находится внутри зеркала ChatGPT-проекта, не изменяй синхронизированные файлы и содержимое `sources/`; соблюдай инструкции родительского каталога.

## Обязательные границы MVP

- React, Vite, TypeScript, React Router, Zustand, Dexie поверх IndexedDB.
- Шесть экранов: Главная, Тренировка, Словарь, Статистика, Профиль, Настройки.
- Локальные профили; общий словарь с тегами; прогресс и история раздельны по профилям.
- Единственная тренировка: казахское слово и четыре варианта перевода на русский, ровно один правильный ответ. Проверка автоматическая, повторение интервальное.
- Bento UI, светлая/тёмная/системная тема, палитры и стили, JSON backup и восстановление, offline PWA.
- Не добавлять WordSet, наборы, аудио, транскрипцию, самооценку, backend, регистрацию, облачную синхронизацию или другие режимы тренировок.
- Теги словаря — классификация слов, а не сущность набора. Темы оформления — отдельная настройка UI. Имена Topic/topics/topicIds в коде, базе и JSON версии 1 сохраняются для совместимости.

## Порядок работы

1. Прочитай документацию и существующий код перед изменениями.
2. Реализуй этапы плана по порядку; сохраняй рабочее приложение после каждого этапа.
3. Бизнес-логику проверки, очереди, повторения и статистики держи вне React-компонентов.
4. IndexedDB — источник долговременных данных. Zustand — состояние интерфейса и текущего сеанса. Не сохраняй словарь или историю в localStorage.
5. Все операции с данными выполняй через репозитории. Ответ, прогресс и счётчики сеанса записывай одной транзакцией; защищай запись от повторного нажатия.
6. Миграции Dexie делай версионными. Не очищай пользовательскую базу для исправления схемы.
7. Проверяй JSON до записи; восстановление и удаления должны быть атомарными и иметь понятное подтверждение.
8. Используй общие UI-компоненты и CSS-токены. Не копируй экраны для разных стилей.
9. Интерфейс и сообщения — на русском; казахские слова сохраняй с исходными буквами. Поддерживай клавиатуру, видимый фокус и доступные статусы ответов.
10. Не выдавай рабочие решения из документации за дополнительно согласованные требования. Если меняешь их, обновляй все связанные документы.

## Правило для проверки кода перед завершением задачи

Запускай eslint в измененных файлах после окончания изменения кода и до завершения задачи. Убедись, что нет ошибок. Если есть ошибки — исправляй их и снова запускай eslint до тех пор, пока не будут исправлены все ошибки
Проверяй TypeScript и production build; тестируй интервалы, неоднозначные варианты, изоляцию профилей, атомарность и импорт. Выполняй ручные проверки шести экранов, перезагрузки, offline production PWA, восстановления backup и оформления на узком экране. Сообщай, какие проверки выполнены и какие ограничения остались. Не добавляй тесты, которые лишь повторяют реализацию.
